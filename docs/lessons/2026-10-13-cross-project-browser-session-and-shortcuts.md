# 持久浏览器与快捷方式复盘

## 本项目结果

- 浏览器从 `undetected-chromedriver` 改为“普通可见 Chrome 独立启动 + 调试端口附加 Selenium”。项目 Profile、现有页面和登录态可跨 CLI 运行复用。
- 准备阶段先检查当前站内页；已登录时不访问首页，无法确认时最多导航一次。
- 演员第一页、后续分页和 FC2 详情全部经过 `PersistentBrowser.navigate()`。相同 URL 不重复跳转，连续导航节流，超时停止加载而不刷新。
- 只在演员目录创建一个 URL，并保持原有 `id_{演员ID} - latest_{最新番号}` 命名格式；作品目录只创建文件夹。

## 可复用经验

- 降低挑战的关键不是伪装更多，而是减少新会话、重复首页访问和刷新验证页。
- 挑战检测应同时检查标题和正文；先等待自动跳转，超时后再要求人工处理，确认后继续观察原页面。
- CLI 退出只断开驱动，不关闭项目 Chrome。用户手动关闭浏览器、系统重启或会话过期后，重新验证属于正常外部状态。
- 所有页面导航必须集中到一个入口。新增页面类型时先复用该入口，并添加离线测试，禁止散落 `driver.get()`、`refresh()` 或临时 WebDriver。

姐妹项目 `leak` 还对不同站点隔离 Profile，并让已验证的 SupJav 会话同步 Cookie/UA 读取静态 HTML；只有明确 403/503 才回退可见浏览器。静态读取不是本项目需要的功能，但“持久会话、单一入口、少访问、不刷新”的原则相同。

## 验收要点

- 假浏览器测试必须证明普通 Chrome 先启动再附加、现有进程可复用、当前登录页不触发准备导航、同 URL 只导航一次、退出不关闭 Chrome。
- 输入测试必须证明登录准备早于菜单，FC2 详情同样走统一入口。
- 输出测试必须证明演员快捷方式保持原有格式，作品目录不含 `.url`。
