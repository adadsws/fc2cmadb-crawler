# 单一 Plan 与任务内容归属整改计划

## 需求与范围

- 使当前项目遵循全局 `AGENTS.md` 的任务规划要求：同一目标在任一时点只有一个当前 Plan。
- 任务规范、补充规范、需求及其补充、相关澄清、变更、样例、验收标准和验证记录统一写入该目标的当前 Plan；后续补充直接更新原 Plan，不为同一目标另建文档。
- 保留 `docs/lessons/` 作为复盘例外；正式项目规则、源码文档和必要交付文档继续履行原有职责，不以它们替代 Plan。
- 保护既有已完成计划的历史记录，不因本次规则整改追溯改写。

## 现状与判断

- 检查时 `docs/plans/` 为空，`docs/finished_plans/` 有三个历史 Plan；当前没有多个并行 Plan。
- 项目根 `AGENTS.md` 只有输出目录及 Cookie 约束，没有写明本项目如何落实单一当前 Plan。
- `AGENT_CONTEXT.md` 含一次性真实验证样例；相同经历已在 `docs/lessons/` 的复盘中记录。架构说明只需保留可复用解析约束。
- 本次是规划约束的项目化落实，不改动爬虫行为、Cookie 文件或历史计划。

## 样例与验收标准

| 输入或状态 | 预期行为 | 预期输出 |
|---|---|---|
| 新的多步骤目标，当前无该目标 Plan | 在 `docs/plans/` 建立该目标唯一的当前 Plan | 需求、设计、实施与验收写在同一文件 |
| 同一目标收到补充规范、样例或验收标准 | 修改该目标的当前 Plan | 仍只有原 Plan，不出现补充规范、样例集或第二个计划文件 |
| 当前目标结束后启动独立目标 | 为新目标另建 Plan | 不复用旧目标 Plan，也不混写不同目标 |
| 目标完成 | 将该 Plan 移入 `docs/finished_plans/` | 当前目录不再保留该目标 Plan，历史记录仍可查 |
| 提炼跨任务经验 | 可写入 `docs/lessons/` | 复盘不替代 Plan 中的需求和验收记录 |
