# FC2 文件夹更新请求间隔实测

## 目标

- 使用 `V:\N\~q %db\q\~02good` 的真实番号，找到较少触发 429 的普通详情页访问间隔。
- 将可验证的保守默认间隔用于 `tools/run_update_fc2_folder_names.bat`，保持已有 429 指数退避和会话内间隔增长。
- 只预览，不执行目录改名；如站点持续限流，记录证据与未验证范围，不声称保证不会 429。

## 人工介入

- 如站点安全验证或登录状态阻断详情页读取，需用户在项目 Chrome 中完成验证；此前先完成不依赖站点的代码与离线测试。

## 阶段记录

- 指定根目录含 96 个不同 FC2 番号；现有详情页默认间隔 2 秒，通用浏览器导航最短间隔 0.8 秒。
- 4 秒间隔的首轮 10 个真实番号均正常；紧接着以同间隔运行完整只预览批次，约第 10 个请求附近出现 429。重试前间隔升至 8 秒，仍再次遇 429，遂停止该次只预览进程。该结果表明 4 秒不足以支撑连续批量查询；短批次成功不能作为完整批次安全依据。
- 等待限流窗口后，用 BAT 加 `--dry-run --interval 12` 处理指定根目录：96 个番号全部走完，耗时 1146.3 秒，日志中 429 为 0；发现待改名 18、跳过 78，其中 3 个番号返回 404。运行前后 96 个匹配目录名完全相同。
- 因 4 秒触发 429、12 秒整批未触发，将默认间隔设为 12 秒。该值是当前站点状态与本目录规模下的实测可用值，不保证其他时段或更大批次绝不触发 429；保留指数退避与 `--interval` 调整入口。
- 实测时发现 BAT 原先忽略 Python 非零退出码，已修复；`--interval 33` 经 BAT 返回 2，`--help` 返回 0。完整离线测试 83 项通过。
